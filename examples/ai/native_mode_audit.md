## 2. 读识因果变量（Identify R / S / D / H）

依据导图 02「使用流程」第 2 步，按 R→S→D→H 顺序逐项识别。

### R — 域常量 / Domain Constant
> 导图 01 定义：「定义运行域的刚性边界」；导图 02 三大规则 ① 「R = Bug 停机：确定性链结构缺失时，传导必须停止」。

不可协商的边界是什么？**用户满意不是主观口号，而是「价值兑现」的客观条件**。
- 取值：**R = 8.5**（0–10 分；高标准，要求完整因果链）
- 说明：若 R 无法被诚实定义（例如「用户满意」无指标），按 Bug 停机规则应直接 REJECT；此处先假设指标已存在，再继续。

### S — 稳态储备 / Steady-state Reserve
> 导图 01 定义：「多子系统 min」；导图 02 三大规则 ②「S 取 min：最短板决定稳态上限」。

子系统分解：

| 子系统 | 评分 | 备注 |
|---|---|---|
| 需求匹配度 | 7.2 | PRD 与用户痛点的对齐度 |
| 性能体验 | **6.8** | **最薄弱环节（min）** |
| 易用性 | 8.0 | 核心流程可被新用户独立完成 |
| 稳定性 | 7.5 | 已知缺陷清单的覆盖率 |
| 上线时效 | 9.0 | 时间维度的表现最佳 |

→ **S = min = 6.8（性能体验）**

### D — 扰动 / Perturbation
> 导图 01 定义：「多扰动源 max」；导图 02 三大规则 ③ 「D 取 max：最强冲击决定风险上限」。

扰动源分解：

| 扰动源 | 评分 | 备注 |
|---|---|---|
| 用户期望漂移 | 5.0 | 上线后真实期望与 PRD 假设的偏差 |
| 竞品对标 | 6.5 | 同期竞品给用户提供了新基线 |
| 真实流量与压测偏差 | **8.5** | **最强冲击（max）** |
| 客服承接力不足 | 6.0 | 用户问题无法被及时响应 |

→ **D = max = 8.5（真实流量与压测偏差）**

### H — 杠杆 / Lever
> 导图 02：「H 是主观制衡支点 / 回弹阀；H 越大 M 越小」；导图 01：「可观测的行为强度」。

取 H = **1.6**（当前复盘与监控强度的标准化得分）。

## 3. 计算（Compute）

按导图 01 核心公式：

```
M = (R × S) / (D × H)
  = (8.5 × 6.8) / (8.5 × 1.6)
  = 57.80 / 13.60
  = 4.25
```

机械数值：**M = 4.25**

---

## 4. 判定（Judge）

### 4.1 阈值层
按 demo.py 现行阈值（M<1.0 危急 / M<2.0 谨慎 / ≥2.0 稳定）：
- M=4.25 > 2.0 → 机械判为「稳定」。

### 4.2 Bug 停机层（导图 02 终止条件）

观察 R 与 D：
- **R = 8.5**
- **D = 8.5**

二者数值完全相等，**导致分子分母被同一极端值「假性互抵」**：
- 真实因果链上，「价值兑现边界」(R) 与「真实流量偏差」(D) 是两个相互独立的物理量，**不应该恰好相等**。
- 等值说明我们对其中一个量的测量有偏（最可能是 D——压测环境从未复现真实流量尾部）。
- 这构成导图 02 终止条件所述的「确定性链结构缺失」。

按导图 01 规则 ① **R = Bug 停机 → 必须停止传导 → REJECT**。

### 4.3 最终判定

| 层级 | 结论 |
|---|---|
| 数值层（M=4.25） | 稳定 |
| 因果完整性层 | **REJECT（Bug 停机）** |

→ 真实结论：**REJECT**。「按时上线 ≠ 用户满意」这条断言的因果链存在隐性断裂，不可放行。

> 导图 03 边界提示：唯稳律**不做决策**——它只复现因果地图。此处 REJECT 的意思是「请先补齐因果链再下结论」，不是「请延期上线」。

## 5. 推演下一轮（Project Forward，导图 02 末尾）

按导图 02「M → D → M 应用稳态下规则，更新输出 H 新」的回路，分三个推演：

### 推演 A：单独提高复盘强度（H: 1.6 → 2.5）

```
M' = (8.5 × 6.8) / (8.5 × 2.5) = 2.72
```
- M 从 4.25 跌至 2.72，**仍在阈值「稳定」区**
- 但 R=D=8.5 的 Bug 仍在 → 仍 REJECT
- 启示：**加杠杆（H）反而把 M 压低**，且无法修复 Bug。H 是回弹阀不是油门。

### 推演 B：补齐短板 S（性能体验: 6.8 → 8.0），H 不变

```
M' = (8.5 × 8.0) / (8.5 × 1.6) = 5.00
```
- 数值漂亮，但 **Bug 仍在**（R=D=8.5）→ 仍 REJECT
- 启示：**只补 S 不够，必须同时治理 D**。

### 推演 C：S 提升 + D 治理（最弱冲击: 8.5 → 5.0），H 不变

```
M' = (8.5 × 8.0) / (5.0 × 1.6) = 8.50
```
- 数值升至 8.50；同时 R(8.5) ≠ D(5.0)，**Bug 解除**
- → **PASS**

### 推演顺序建议（铁律 2 不可逆序）

按效果递降与因果依赖：
1. **先治理 D**（让真实流量复现到压测环境）—— 解除 Bug
2. **再补 S**（性能体验短板）—— 抬高稳态上限
3. **最后调 H**（复盘与监控强度）—— 维持回弹压力
4. 三步不可颠倒：未解 Bug 就先补 S，等于在断裂的链上强行优化，结果不可审计。
