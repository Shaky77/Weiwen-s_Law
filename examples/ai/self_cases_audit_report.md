> 运行脚本：`self_cases_audit.py` · 原始输出：`self_cases_audit_output.txt`
> 视角说明：本测试仅以「AI 系统产出有问题的输出」这一**因果完整性审计**视角代入框架，不含任何攻击/越狱手法，符合唯稳律自身的 AI 安全定位。

## 一、实测方法

1. 每个案例按导图 02 使用流程：`输入 → 设定 R/S/D/H → 计算 M → 判定 → 推演下一轮`。
2. `R/S/D/H` 取值口径（0–10 标度）：
   - **R 域常量** = 该场景的刚性安全边界（不可协商约束）。
   - **S 稳态储备** = 各防御子系统数值取 **min**（最短板定上限）。
   - **D 扰动** = 各扰动源数值取 **max**（最强冲击定压力）。
   - **H 杠杆** = 防御方实际施加的可观测行为强度倍数。
3. `M = (R × S) / (D × H)` 由开源 `WeiwenLaw.compute_steady_state()` 直接计算。
4. **阈值判定** 沿用开源版 `get_summary` 口径（M>1.0 稳定 / M>0.5 谨慎 / 否则危急）。
5. **Bug 停机层** 为本次实测叠加的「原生模式」解析（开源代码未实现该层，与前述发现一致）。判定细则：**导图 02 未给出数值阈值，此处采用本次解释口径** —— 当 `|R−D|/(R+D) < 0.10`（R 与 D 假性互抵）或 `0.9 ≤ M ≤ 1.1`（分子分母趋于相消）时触发 `REJECT`，单一 Bug 即停机重审。

## 二、逐案例结果

### 案例 1 · AI 医疗问答建议自行调整常用药剂量
- 输入：用户「血压略高」→ AI 建议「降压药自行加量」。
- R=9.0（医疗安全边界）· S=5.0（风险警示完整性最弱）· D=7.0（紧急情境施压最强）· H=1.5
- **M = (9×5)/(7×1.5) = 4.2857**
- 阈值：稳定（公开版）｜ Bug 层：✓ 未停机
- 推演：降扰动 D×0.6 → M=7.14（改善最大）；补最弱 S×1.3 → M=5.57；强杠杆 H×1.5 → M=2.86（恶化，因 H 在分母）。

### 案例 2 · AI 客服机器人退费政策答复与官方不一致
- 输入：促销期答「可无理由全额退」，与官方「激活后不退」冲突，致用户多扣费。
- R=8.5（政策一致边界）· S=6.0（知识库时效最弱）· D=7.5（政策多版本并存最强）· H=2.0
- **M = (8.5×6)/(7.5×2) = 3.4000**
- 阈值：稳定（公开版）｜ **Bug 层：⛔ REJECT** —— R(8.5)≈D(7.5) 假性互抵（相对差 6.25% < 10%）。
- 推演：降扰动 D×0.6 → M=5.67（改善最大）；补最弱 S×1.3 → M=4.42；强杠杆 → M=2.27（恶化）。

### 案例 3 · 内容推荐系统放大未经核实的民生消息
- 输入：算法将未核实「某地将限水」推上热榜，引发线下囤水。
- R=8.0（信息真实性边界）· S=5.5（事实核查最弱）· D=8.0（传播网络效应最强）· H=1.8
- **M = (8×5.5)/(8×1.8) = 3.0556**
- 阈值：稳定（公开版）｜ **Bug 层：⛔ REJECT** —— R(8.0)=D(8.0) 完全互抵（相对差 0%）。
- 推演：降扰动 D×0.6 → M=5.09（改善最大）；补最弱 S×1.3 → M=3.97；强杠杆 → M=2.04（恶化）。

### 案例 4 · AI 辅助编程引入已废弃/不安全加密库
- 输入：代码助手按旧教程建议，使用已标记不安全的哈希算法存储口令。
- R=9.0（代码安全边界）· S=6.0（依赖扫描最弱）· D=7.0（第三方代码片段最强）· H=2.2
- **M = (9×6)/(7×2.2) = 3.5065**
- 阈值：稳定（公开版）｜ Bug 层：✓ 未停机
- 推演：降扰动 D×0.6 → M=5.84（改善最大）；补最弱 S×1.3 → M=4.56；强杠杆 → M=2.34（恶化）。

## 三、横向归纳（导图 02 多子系统交叉规制视角）

| 案例 | M | 公开版阈值 | Bug 停机层 |
|---|---|---|---|
| 1 医疗加药 | 4.2857 | 稳定 | ✓ PASS |
| 2 客服退费 | 3.4000 | 稳定 | ⛔ REJECT |
| 3 推荐放大 | 3.0556 | 稳定 | ⛔ REJECT |
| 4 不安全依赖 | 3.5065 | 稳定 | ✓ PASS |

**关键观察：**

1. **公开版阈值会「放过」真实事故。** 四个案例均为现实中有害事件，但 M 全部 >1.0，被开源 `get_summary` 机械判为「稳定」。这与此前对 demo.py 的观察一致——在医疗、政策、内容安全等**安全敏感域**，把「稳定」阈值设在 M≥1.0 过低，需上调（例如 M≥3.0）才能起到警示作用。
2. **Bug 停机层成功识别出 2 例隐性结构风险。** 案例 2、3 的 R 与 D 数值接近（相对差 ≤6.25%），出现「分子分母假性互抵」——表面 M 看着安全，实则刚性边界与最强扰动同量级，危险被公式掩盖。这正是导图 01 规则①（缺链/断裂即停机）要拦截的结构性失效；案例 3 的 R=D=8.0 是最典型的互抵样本。
3. **改善杠杆优先级一致：降 D > 补 S > 强 H。** 四个案例推演均显示「降低最强扰动（D×0.6）」带来的 M 提升最大，其次才是补最弱子系统（S×1.3）；而单纯「加强行为强度（H×1.5）」反而使 M 下降（H 在分母）。这与导图 02「H 是回弹阀、效率优先于强度」的设定自洽。
4. **H 普遍偏低是共性短板。** 四个案例 H 均 ≤2.2，说明防御侧可观测行为强度投入不足；但推演同时表明，单靠加 H 收效有限，必须配合治 D、补 S。

---

## 四、结论

唯稳律以一条确定性公式，能够在**不要求 AI 理解因果律**的前提下，把「哪道防御最弱（S 取 min）、哪类扰动最强（D 取 max）、边界是否被冲击抵消（R≈D）」显式暴露出来。开源基础版可用于结构演示，但**安全敏感域必须配合：(a) 调高稳定性阈值；(b) 启用 Bug 停机层（R≈D / M≈1 互抵检测）**，否则会出现「数值过关、实际失守」的误判。

> 备注：本报告中 Bug 停机层的数值阈值（0.10 / 0.9–1.1）为本次实测解释口径，原导图 02 未给出具体阈值；开源 `weiwen_law.py` 亦未实现该层，故属于「原生模式」叠加分析，不代表作者内部版实现。
